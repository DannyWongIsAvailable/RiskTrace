# RiskTrace 前端设计系统

## 1. 设计目标

RiskTrace 使用克制、专业、数据优先的企业级 SaaS 界面。

设计的首要目标不是“视觉炫酷”，而是帮助用户：

- 快速扫描采购风险；
- 比较金额、状态和时间；
- 核验证据来源；
- 理解系统判断；
- 安全执行处置操作；
- 清楚知道当前操作结果。

界面应给人可靠、稳定、可审计的感受，而不是营销化、娱乐化或实验化。

## 2. 基础样式分层

全局设计令牌位于：

```text
src/styles/tokens.css
```

样式职责：

- `tokens.css`：颜色、字体、间距、圆角、阴影、布局尺寸等设计决策；
- `reset.css`：浏览器默认样式归一化；
- `element.css`：Element Plus 主题变量和组件覆盖；
- `utilities.css`：少量跨页面布局工具；
- 组件 Scoped CSS：组件自身结构与局部响应式规则。

禁止在组件中复制设计令牌的具体值。必须使用 CSS 变量。

## 3. 色彩系统

### 3.1 主色

主蓝色用于：

- 当前导航；
- 主按钮；
- 链接；
- 选中状态；
- 关键交互焦点。

不得为了“更丰富”而在不同页面使用不同主色。

### 3.2 语义色

绿色、黄色、橙色和红色仅用于有明确含义的状态，例如：

- 成功或已完成；
- 需要关注；
- 高风险；
- 重大风险或错误。

颜色不能成为表达风险的唯一方式。必须同时提供文本标签，并优先使用 `StatusTag.vue`。

### 3.3 中性色

中性灰用于：

- 页面背景；
- 卡片边界；
- 次要文字；
- 分割线；
- 禁用状态；
- 表格辅助信息。

## 4. 字体与信息层级

统一使用 `--rt-font-family` 定义的系统字体栈。

建议层级：

- 页面标题：24–32 px，较强字重；
- 章节标题：16–18 px；
- 卡片标题：16 px；
- 正文：14 px；
- 元数据与辅助信息：12–13 px。

要求：

- 中文标题不要使用全大写效果；
- 避免同时使用过多字重；
- 辅助信息不能小到难以阅读；
- 金额、编号和时间应保持清晰对齐；
- 小型英文眉题可使用大写和适量字距，但不得滥用。

## 5. 间距系统

使用从 `--rt-space-1` 到 `--rt-space-12` 的 4 px 间距体系。

要求：

- 默认页面内边距使用 `--rt-space-6`；
- 移动端可降为 `--rt-space-4`；
- 相同层级的卡片和字段保持一致间距；
- 没有明确布局理由时，不使用 17 px、23 px、31 px 等任意值；
- 优先通过间距表达层级，而不是添加更多边框和装饰。

## 6. 页面与内容面

运营内容面优先使用 `BaseCard.vue`。

卡片原则：

- 使用轻边框和极轻阴影；
- 圆角统一；
- 卡片标题、内容和操作区结构清晰；
- 避免无意义嵌套卡片；
- 只有当内部对象具备独立操作或独立语义时才使用嵌套面板；
- 不用渐变、大面积彩色背景和装饰图案制造层级。

## 7. 通用组件

### `PageHeader`

用于页面身份、说明、面包屑和页面主操作。

### `SectionHeader`

用于页面内部章节标题和局部操作。

### `BaseCard`

通用内容承载面。

### `BaseTableCard`

统一表格标题、工具区、状态区和底部分页区域。

### `MetricCard`

用于展示关键指标，避免过度装饰和无意义趋势。

### `FilterBar`

集中放置筛选条件和查询操作。

### `StatusTag`

统一显示风险、流程和任务状态。

### `InlineNotice`

用于上下文说明、提醒和警告，不代替系统级消息反馈。

### `DescriptionList`

展示结构化键值详情。

### `PaginationBar`

统一分页摘要和分页控件。

### `ConfirmActionDialog`

用于需要确认的业务操作，并支持强制填写业务理由。

### 状态组件

- `LoadingState`：真实加载；
- `EmptyState`：无数据；
- `ErrorState`：可恢复错误。

创建同类组件前，应先通过 Props 和 Slots 扩展上述组件。

## 8. 导航

桌面端：

- 使用固定左侧导航；
- 顶部栏保持可见；
- 当前导航状态明确；
- 导航层级尽量扁平。

移动端：

- 使用抽屉式导航；
- 入口使用明确的文本或标准图标按钮；
- 不依赖悬停操作。

导航标签应使用业务术语，禁止使用难以理解的缩写和“聪明但模糊”的命名。

## 9. 表格

表格统一放在 `BaseTableCard` 中，并优先使用 Element Plus Table。

建议：

- 身份类字段放左侧；
- 金额和数字统一对齐；
- 状态使用 `StatusTag`；
- 行级操作数量保持克制；
- 主要操作和次要操作有明显层级；
- 分页位于卡片底部；
- 窄屏允许横向滚动；
- 加载、空数据和错误状态必须完整；
- 不通过背景色堆叠制造“彩色表格”。

## 10. 表单

统一使用 Element Plus 表单控件。

要求：

- 风险、金额、供应商、账户和审批字段必须使用明确标签；
- 必填、格式和业务校验信息靠近字段；
- 每个表单只保留一个明确主操作；
- 提交期间禁止重复提交；
- 可恢复错误后保留已输入内容；
- 危险操作、风险覆盖和强制放行必须确认并填写业务理由；
- 不用占位文字替代长期可见标签。

## 11. 按钮与操作层级

- 每个页面或表单只设置一个主要动作；
- 次要动作使用普通或文本按钮；
- 危险操作使用危险语义，但不应在页面中过度出现；
- 操作名称使用明确动词，例如“暂缓付款”“提交复核”“重新评估”；
- 避免“确定”“处理”“操作”等缺少上下文的按钮文字；
- 纯图标按钮必须提供无障碍标签和悬浮说明。

## 12. 图标系统

### 12.1 唯一图标库

通用界面图标只允许使用 `@element-plus/icons-vue`。
所有业务代码必须通过 `src/icons/index.ts` 中的 `AppIcons` 语义映射访问图标。

禁止：

- 业务文件直接导入 `@element-plus/icons-vue`；
- 引入第二套图标库；
- 混用不同图标家族；
- 使用 Emoji、Unicode 符号、文字首字或 CSS 方块代替图标；
- 随机生成通用 SVG 图标。

### 12.2 风格与语义

- 导航、按钮、筛选和表格操作默认使用线性图标；
- 填充图标仅用于成功、警告、错误等明确状态；
- 同一业务语义必须在全项目使用同一图标；
- 图标不能替代必要文字；
- 状态必须同时提供图标、颜色和文字中的至少文字表达；
- 不为每张卡片、标题和指标添加装饰图标。

### 12.3 尺寸

统一使用以下图标尺寸令牌：

```css
--rt-icon-size-xs: 14px;
--rt-icon-size-sm: 16px;
--rt-icon-size-md: 18px;
--rt-icon-size-lg: 20px;
--rt-icon-size-xl: 24px;
--rt-icon-size-state: 40px;
```

推荐：

- 表格行内操作与普通按钮：16px；
- 导航与顶栏操作：18px；
- 标题辅助图标：20px；
- 重点入口：24px；
- 空状态与结果状态：40px。

业务组件不得自行创造任意尺寸。

### 12.4 颜色

普通图标默认 `color: currentColor`，继承所在文本或按钮颜色。
只有成功、警告、错误、禁用等明确状态可以使用对应语义色。
普通搜索、查看、编辑、下载等图标不得单独设置彩色。

### 12.5 图标按钮与无障碍

纯图标按钮统一使用 `IconButton.vue`，并必须提供：

- Tooltip；
- `aria-label`；
- 可见键盘焦点；
- 明确禁用状态；
- 危险操作语义。

图标旁已有明确文字时，图标应设置为装饰性内容，避免屏幕阅读器重复朗读。

完整规范见 `docs/ICON_SYSTEM.md`。

## 13. 状态与反馈

用户执行操作后必须得到明确反馈：

- 操作进行中；
- 操作成功；
- 操作失败；
- 是否可以重试；
- 当前数据是否已更新。

不要只依赖按钮消失、颜色变化或页面跳转暗示结果。

## 14. 响应式设计

至少检查：

- 常规桌面宽度；
- 窄桌面或平板宽度；
- 手机宽度。

移动端允许：

- 指标卡纵向排列；
- 表格横向滚动；
- 筛选区域折叠；
- 页面操作换行；
- 侧栏变为抽屉。

禁止简单缩小全部字体来适配移动端。

## 15. 动效

动效必须短、轻量且有功能意义。

要求：

- 尊重 `prefers-reduced-motion`；
- 禁止循环装饰动画；
- 只有在真实加载时使用加载动画或骨架；
- 避免夸张弹跳、旋转和发光效果；
- 页面切换不需要复杂过渡。

## 16. 静态资源政策

优先复用：

```text
public/brand/
src/assets/
```

禁止：

- Emoji；
- 远程图库图片；
- 随机生成的占位 SVG；
- 与业务无关的插画；
- 大体积未压缩图片；
- Base64 嵌入核心资源。

新增资源时必须：

- 使用语义化文件名；
- 压缩体积；
- 说明用途；
- 保证许可和来源清晰；
- 考虑深色、浅色背景和响应式使用方式。

## 17. 禁止的视觉模式

- 每个页面使用不同颜色体系；
- 大面积渐变和发光背景；
- 用 Emoji、Unicode 符号、文字首字或 CSS 图形代替图标；
- 混用多套图标库或绕过 `@/icons` 直接导入图标；
- 用无意义英文口号填充页面；
- 用假图表和随机数字制造完成度；
- 卡片层层嵌套；
- 同一页面出现多种圆角和阴影；
- 使用过多标签色和状态色；
- 把运营后台设计成营销首页。
